# Chico Admins — التشغيل والنشر والاستعادة

إصدار 1.3.0 · 15 أكتوبر 2026. المصدر منفذ. جرى ضبط عنوان المشروع Chico ومفتاحه العام، والتحقق من /auth/v1/settings بنجاح. تطبيق Migrations وAuth Admin يحتاج مفتاح الخادم؛ لم ينفذا على قاعدة المستخدم. إعدادها يتم يدويًا بالخطوات التالية، دون تثبيت الإضافات التي رفضها المستخدم.

| الجزء | الاختيار |
|---|---|
| التطبيق | Next.js App Router، React، TypeScript، CSS داكنة بألوان حالات ورتب متعددة |
| الحسابات والبيانات والمرفقات | Supabase Auth، PostgreSQL، Storage الخاص |
| النشر الرئيسي | Vercel بإعداد `vercel.json` المرفق |

مسار Next.js بُني فعليًا، لذلك أُرفق إعداد Vercel له. يمكن أيضًا تشغيله على استضافة Node.js تدعم Next.js باستخدام `build:vercel` ثم `start:vercel`.

## 2. التشغيل المحلي

استخدم Node.js 24 وpnpm 11.25.0 ، وفك المصدر في مجلد خاص:

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm run env:setup
```

ينشئ السكربت `.env.local` بمفاتيح عشوائية دون طباعتها، ويحافظ على الملف السابق. أكمل القيم التالية داخله:

| المتغير | المصدر |
|---|---|
| `SUPABASE_URL` | عنوان مشروع Supabase |
| `SUPABASE_PUBLISHABLE_KEY` | Publishable أو anon القديم |
| `SUPABASE_SECRET_KEY` | Secret الخاص بالخادم أو service_role القديم |
| `SESSION_ENCRYPTION_KEY` | 32 بايت بصيغة base64url؛ يولدها السكربت |
| `RATE_LIMIT_HMAC_KEY` | مفتاح مستقل لبصمة Username في حدود المحاولات؛ لا يُستخدم IP |
| `APP_ORIGIN` | العنوان فقط دون مسار أو شرطة أخيرة؛ محليًا `http://localhost:3000` |

لا تضف `NEXT_PUBLIC_` للأسرار، ولا ترفع `.env.local` إلى Git. تغيير مفتاح التشفير أثناء التشغيل يحتاج إجراءً يلغي الجلسات القديمة.

```sh
pnpm run env:check
pnpm run typecheck
pnpm test
pnpm run build:vercel
pnpm run dev:vercel
```

فحص البيئة يتحقق من الصيغة فقط. الاختبارات تعمل دون قاعدة إنتاج وتطبق SQL داخل PostgreSQL/PGlite. لا توجد كلمات مرور افتراضية.

## 3. المالك والاعتماد

لا تنشئ حساب المالك من التسجيل العام؛ `Owner Chico` محجوز. `/setup` و`/preview` تحولان إلى `/app`، و`/api/bootstrap` مغلق. الواجهة لا تمنح ملكية لأحد، وأول مسجل يظل بانتظار الموافقة.

بعد تطبيق المخطط وإكمال بيئة الخادم، شغّل من مجلد المشروع على جهاز المشغل الموثوق:

```sh
node --env-file=.env.local scripts/provision-owner.mjs
```

اترك Username الافتراضي `Owner Chico`، وأدخل اسمك الإداري الفعلي داخل اللعبة ورتبتك وتاريخ انضمامك الصحيح. أدخل كلمة المرور المطلوبة في الطرفية؛ تظهر نجوم فقط ولا تُحفظ في ملف العملية أو المصدر أو السجل. لا ترسل مفتاح الخادم أو الكلمة في الشات. ملكية الموقع لا تغير رتبة اللعبة ولا تعطي Helper حق نشر الإحصائيات.

الأداة ترفض وجود Owner آخر أو اسم مستخدم قائم؛ لا ترقي حسابًا بالاسم ولا تعيد تعيين كلمة مروره. تنشئ هوية Auth تقنية عشوائية، ثم تربط العضو والحساب ومنحة Owner في معاملة واحدة، مع قفل يمنع تعدد الملاك.

تحفظ الأداة `.owner-provision.json` محليًا قبل طلب إنشاء الهوية. يحتوي معرف العملية والعنوان التقني وبيانات اللعبة المطلوبة فقط، دون كلمة مرور أو مفتاح. لا ترفعه إلى Git ولا تنقله إلى مجلد الويب. إذا انقطع الاتصال، احتفظ بالملف ومن المجلد نفسه استخدم:

```sh
node --env-file=.env.local scripts/provision-owner.mjs --resume
```

الاستئناف يبحث عن العنوان التقني نفسه ولا ينشئ هوية ثانية عند نتيجة مبهمة. إذا لم يجدها، يتوقف حتى يراجع المشغل مزود Auth ويتأكد من انتهاء الطلب السابق؛ لا تحذف ملف العملية لتجاوز الحماية. إذا كان الحساب قد اكتمل، يكتشفه دون تغيير كلمة المرور. لفحص UUID معروف دون كتابة:

```sh
node --env-file=.env.local scripts/provision-owner.mjs --check USER_UUID
```

بعدها يسجل أعضاء الفريق بأنفسهم؛ Owner أوResponsible يعتمدهم ويحدد اسم الإداري ورتبته وتاريخ الانضمام. Administrator / Level 3 لا يعتمد الحسابات ولا يدير الفريق حتى مع منح قديمة. المسؤول لا يغير ملكية Owner أو حسابه المحمي. العضو يعدل Username والصورة وكلمة المرور؛ الاسم الظاهر والرتبة للمسؤول. تعطيل الحساب يلغي الوصول ويحفظ السجل.

## 4. النشر على Vercel

1. ارفع المصدر إلى مستودع Git خاص بحسابك، دون الأسرار أو بيانات المستخدمين أو `node_modules` أو `dist`.
2. استورده في Vercel واختر Next.js وNode.js 24. الملف `vercel.json` يحدد Install Command وBuild Command.
3. أضف متغيرات الخادم في Project Settings → Environment Variables. اجعل `APP_ORIGIN` مساويًا لعنوان Production الثابت دون شرطة أخيرة.
4. استخدم قاعدة اختبار ومفاتيحها في Preview. لا تربط فروع المعاينة ببيانات الإنتاج.
5. انشر، وأعد النشر بعد تغيير متغيرات البيئة. اختبر التسجيل والاعتماد والمرفقات والأدوار على العنوان الحقيقي.

Cookie الإنتاج اسمه `__Host-chico-session`، وهو Secure وHttpOnly وSameSite=Lax، لذلك يحتاج HTTPS. حفظ الدخول: 30 يومًا كحد أقصى و 7 أيام خمول. الدخول العادي: 12 ساعة وساعة خمول. إلغاء الجلسة وسحب الصلاحيات يفرضان منع الوصول عبر قاعدة البيانات.

نسخة Sites هنا خاصة بالمالك، ولها حد وصول ChatGPT خارجي أيضًا. نشرها يثبت وجود نسخة المراجعة، ولا يثبت تشغيل Auth أو قاعدة إنتاج على Vercel.

## 6. قواعد الأداء

الأسبوع يبدأ الاثنين 03:00 السعودية. تخزن اللحظات UTC وتعرض في `Asia/Riyadh`. حدد التذاكر كعدد يومي أو إجمالي الأسبوع حتى القياس؛ لا يخلط النظام النمطين لعضو في أسبوع واحد. الساعات والتقييم أحدث لقطة، والتقرير الأسبوعي مرجع مستقل لا يضاف إلى اليومي.

البيانات غير المضافة تختلف عن صفر. يعرض ملخص الفريق عدد المحدثين والإنجاز المسجل. كل تقرير يحفظ الرتبة والأهداف وإصدار السياسة. تصحيح المنشور يحتاج القيادة وسببًا ورقم النسخة الحالي، ويحفظ القيمة السابقة. التكرار المطابق لا يضاعف التقارير.

## 7. الاستيراد والخصوصية

الاستيراد لصاحب الموقع وResponsible فقط، بحد 4 ميجابايت و 500 سجل، مع 25 سجلًا في صفحة المراجعة. اختر ورقة Excel والنوع اليومي أو الأسبوعي، والتاريخ ومعنى التذاكر وربط UUID الداخلي أو الاسم المستعار المطابق بعد مراجعة. لا تستخدم Discord ID أو بريدًا أو هاتفًا للمطابقة.

المعاينة الأولى محلية. عند «مراجعة التغييرات على الخادم» تُعاد كتابة الأعمدة التشغيلية المسموحة فقط إلى CSV خاص: المعرف الداخلي والاسم المستعار والرتبة وتاريخ الانضمام للفريق ووقت القياس والأرقام. لا يحفظ المصنف الأصلي أو أوراقه المخفية أو خصائصه أو اسم ملفه الشخصي. البصمة لبـايتات المصدر التشغيلي المنقى، وليست لبـايتات الملف الأصلي. الأسماء التي تبدأ بمحارف صيغ تعبر الترميز دون تغيير هويتها. الخادم يتحقق من المعرفات والتواريخ والأطوال والأرقام.

راجع «سينشأ/سيتحدث/دون تغيير/مرفوض» ومعاينة قبل/بعد. تصحيح تقرير قائم يستخدم معرفه الثابت ونسخته الحالية وسببًا موثقًا. إعادة نفس المصدر تستخدم الملف المحفوظ؛ أي اختلاف متزامن في النسخة يرفض الحفظ. الدفعة معاملة واحدة، وفشل صف يرجعها كلها. الصفوف غير المختارة لا تستورد. تعرض القيم الخام وتقرير الأخطاء للتنزيل؛ الفاصلة العشرية 12,5 تعني 12.5 ، أما 1,234 فيرفض كقيمة ملتبسة حتى يوضح المصدر.

الفلاجات التراكمية اختيار مراجعة مستقل، لا تجمع الإجمالي كواقعة جديدة. المصدر المنقى يُعاد قراءته على الخادم لمطابقة الأرقام والشكاوى والطلبات والرسائل. التقرير الأسبوعي يستخدم إجمالي الأسبوع. تاريخ مصدر مستقبلي لا يعكس اليوم والشهر تلقائيًا.

في ترقية 1.0: تحذف معرفات IP المشتقة ومعلومات الجهاز والهوية الخارجية وأسماء الملفات القديمة من بيانات التطبيق. تُحجر مصادر الملفات السابقة وتمنع قراءتها من التطبيق وStorage بصلاحيات المستخدم حتى مراجعة المشغل؛ لا يُفترض أن ملفًا قديمًا خالٍ من الهوية. لا تُعد رفعه كما هو. راجع محتواه خارج مساحة التشغيل، وأعد رفع نسخة تشغيلية منقحة مع توثيقها. الحجر لا يحذف البايتات القديمة؛ يحتفظ المشغل بها أو يتلفها وفق قرار الاحتفاظ المعتمد. قاعدة الإصدار الحالية لم تربط ببيانات إنتاج فعلية أثناء التنفيذ.

للتنظيف الدوري للمصادر غير المرتبطة الأقدم من 7 أيام:

```sh
node --env-file=.env.local scripts/cleanup-sources.mjs
```

السكربت يعلّم المرشحين أولًا، ثم يحذف البايتات ويكمل حذف السجل. لا ينظف الأدلة المرتبطة بتقارير أو إصدارات أو دفعات أو مراجعات حية. يمكن تكراره عند فشل جزئي؛ لا يعد وجود السكربت تشغيلًا لجدولة حقيقية.

## 8. الانضباط والأرصدة

الفلاجات تراكمية. «لم تُراجع» تختلف عن صفر مؤكد؛ استخدم «مراجعة الإجمالي» لتثبيت الرصيد التاريخي أو صفر حقيقي من مصدر موثق.

7–9 فلاجات تحتاج متابعة Moderator؛ من 10 تظهر حالة تستلزم مسار تدريب. المسؤول يسجل قرار الإيقاف وينفذه في اللعبة. التسلسل: انتظار التدريب → التدريب → انتظار العودة → اعتماد العودة. العودة لا تحذف الفلاجات.

كل تحذيرين غير مستهلكين يتحولان إلى توبيخ مرة واحدة. إلغاء تحذير مصدر يلغي التوبيخ المشتق. ثلاثة توبيخات تنشئ مراجعة واحدة مرتبطة بالوقائع، ويمكن حسمها بسبب موثق. إلغاء واقعة مصدر يسحب المراجعة إذا هبط العدد دون ثلاثة. الفصل قرار مستقل؛ الموقع لا يغير صلاحيات اللعبة آليًا.

الطلب المعلق لا يخصم الرصيد. القبول فقط يخصم العدد، بعد إعادة فحص الرصيد في المعاملة نفسها؛ القبول المتكرر مرفوض. الرفض أو إلغاء طلب معلق يحفظ التاريخ ولا يغير الرصيد. الرصيد يتجدد تلقائيًا عند أول الشهر بتوقيت السعودية، من حساب الطلبات المعتمدة لذلك الشهر؛ لا يحتاج مهمة تصفير ولا يحذف سجلًا. تمنع الفترات المتداخلة ولو اختلف المصدر. يحفظ كل طلب جديد الرتبة والحصة وإصدار سياسة الرصيد وقت تسجيله؛ الطلب القديم دون لقطة لا تُخترع له سياسة تاريخية. الأرصدة المعروضة للشهر الحالي، والأهداف المؤرشفة من رتبة وسياسة الفترة. الإجازة بأيام كاملة، والطلب الممتد لشهرين يقسم. التبرير قبل المناوبة بأكثر من ساعة مع بديل مقبول. للعضو الجديد يوم إجازة بعد 14 يومًا خلال أول 30 يومًا، حسب بدء الطلب. الإجازة لا تخفض الهدف. أرصدة القيادة تبدأ «لم تُضبط» حتى يحددها Owner أوResponsible. طلبات الموقع تحتاج رابط رسالة Discord بصيغة channels/server/channel/message، ولا تُرسل رسائل Discord تلقائيًا. الرصيد الشهري وحد فترة العضو الجديد يفحصان بصورة مستقلة حتى لا يؤثر ترتيب قبول الطلبات على الاستحقاق.

## 9. الاستعادة والملكية

المخول يتحقق من عضوية الحساب قبل إصدار رمز الاستعادة. الرمز لمدة 15 دقيقة ولمرة واحدة، وتخزن بصمة الرمز. عند البدء تحفظ كلمة المرور الجديدة مشفرة مؤقتًا لإتمام العملية نفسها، ثم يمحى التشفير عند الإكمال؛ لا تسجل الكلمة في التدقيق أو المتصفح. العضو يختار كلمة المرور الجديدة بنفسه؛ تُلغى جلساته القديمة. لا يرسل النظام رموزًا إلى أشخاص تلقائيًا.

نقل الملكية يحتاج تحقق كلمة مرور حديث وتأكيد `TRANSFER OWNERSHIP` وحسابًا فعالًا آخر. يوجد مالك واحد، وتتسلسل تغييرات الصلاحيات لمنع تغير الهدف أثناء القرار. تغيير الرتبة أو نقل الملكية يبطل رموز الاستعادة القديمة للأهداف المتأثرة، ولا يتم خلال استعادة نشطة.

استعادة مالك فقد كل الوصول تحتاج مشغل قاعدة مخولًا بعد إثبات هويته، عبر Auth Admin مع توثيق التدخل وإلغاء جلساته ورموزه القديمة. لا توجد صفحة تجاوز أو إعادة فتح Bootstrap.

### التعامل مع نتيجة تغيير كلمة مرور ملتبسة

تغيير كلمة المرور والاستعادة يشتركان في عملية دائمة واحدة. عند بدئها تلغى الجلسات وتحجب الجلسات الجديدة وتغييرات الرتبة/الملكية المتأثرة وإصدار رمز آخر. إذا نجح مزود الدخول ثم تعطل إكمال SQL، يمكن إعادة محاولة الإكمال دون كتابة كلمة أخرى. انتهاء صلاحية الرمز بعد بداية صحيحة لا يفسد الإكمال.

عند timeout أو وفاة العامل أثناء طلب المزود، تبقى العملية applying/ambiguous محجوبة؛ لا يعاد إطلاق كاتب آخر بانتهاء مهلة فقط. المشغل يتحقق من نتيجة مزود Auth ومن انتهاء الطلب السابق قبل التدخل. بعد تأكيد النتيجة فقط:

```sh
node --env-file=.env.local scripts/reconcile-recovery.mjs --claim UUID --resolution confirmed_applied --reason "verified provider outcome and terminated request" --confirmed-no-pending-auth-request
```

إذا تأكد أن الطلب لم يطبق وانتهى، استخدم confirmed_not_applied؛ تعود العملية reserved لنفس الرمز والكلمة المختارة. لا تختَر نتيجة لمجرد مرور الوقت. هذه أداة خادم بمفتاح الخدمة، وليست زر تجاوز للعضو أو Admin. الاختبار الآلي يغطي الحجب، انتهاء الرمز، الإكمال المتكرر، ومسار التسوية؛ قبول المزود الحي لم ينفذ.

## 10. النسخ الاحتياطي والرجوع

النسخة الكاملة تشمل مصدر Git وSHA، وجداول `public.chico_*` و`chico_private`، وهويات Auth اللازمة للربط، وبايتات ملفات Storage، وإعدادات Auth وبيئة الخادم. احفظها مشفرة خارج Git لدى المشغل.

استخدم مسار Supabase الرسمي للنسخ والاستعادة أو `pg_dump` لدى مشغل مخول. تحقق من وجود المخطط الخاص وهويات Auth، وانسخ Bucketَي `chico-files` و`chico-avatars` منفصلين بالأسماء نفسها. نسخة قاعدة البيانات وحدها لا تحفظ بايتات المرفقات.

قبل استيراد الإنتاج أو تغيير المخطط، خذ نسخة وسجل SHA وإصدار المخطط. استعدها في مشروع اختبار معزول، وافحص الأعداد ومعرفات الربط والمرفقات. بعد الاستعادة، ألغِ جلسات التطبيق ورموز الاستعادة المسترجعة واطلب دخولًا جديدًا.

الرجوع إلى Deployment سابق يعيد الكود فقط؛ لا يعكس بيانات أو Migrations. استعادة المخطط تحتاج نسخة قاعدة متوافقة واختبارًا مستقلًا. لا تحذف النسخة القديمة كجزء من الرجوع.

## 11. اعتماد التشغيل

اختبر حسابات معلق وHelper وSN.Helper وModerator وAdministrator وResponsible وOwner على العنوان الحقيقي، بما في ذلك الطلب المباشر وحفظ الدخول والخروج والاستعادة والمرفقات. جرّب الكمبيوتر وSafari على iPhone وChrome على Android، وأحجام 320 و 390 و 768 و 1440 بكسل، وتحقق من RTL والحوارات والتباين. هذه الفحوص الحية والبصرية والاستعادة السحابية لم تنفذ هنا.

للدعم اجمع نوع الخطأ والتوقيت والعملية ونسخة المصدر دون كلمات مرور أو Cookies أو مفاتيح. عرض التدقيق يبدأ بآخر 100 عملية، مع تصفية محلية وصفحات وزر تحميل الأقدم. الفاعل والهدف بأسماء العرض، وتفاصيل قبل/بعد بأسماء حقول مفهومة دون JSON تقني في واجهة العضو. لا تحفظ كلمات المرور أو رموز الاستعادة أو ترويسات العميل في سجلات الأخطاء.

## 12. نظام النقاط وسجل العضو

الحد الأساسي 100 نقطة. الأوزان الافتراضية: التذاكر40، الساعات25، التقييم20، المهام15. النتيجة = الحد الأساسي × مجموع (الوزن × نسبة الإنجاز حتى100%) ÷ مجموع الأوزان المطبقة على الرتبة. المهام غير المطلوبة تُستبعد من الوزن؛ المفقودة المطلوبة تحتسب صفرًا. الملخص الأسبوعي مرجع أول، وإلا أحدث لقطة، وعدد التذاكر اليومي يجمع أحدث قيمة لكل يوم فقط. الساعات والتقييم لا يجمعان.

تغييرات الأوزان تحفظ إصدارًا جديدًا وتطبق وفق وقت القياس؛ التقارير القديمة تحتفظ بإصدارها. تعديل نقاط عضو موجب أو سالب يحتاج سببًا وتحقق كلمة مرور حديثًا، وإلغاؤه يحفظ السجل. لا ينقص المجموع عن صفر، والمكافأة قد ترفعه فوق الحد الأساسي. الرتب القيادية بلا أهداف أداء لا تُمنح نتيجة افتراضية. التوب لثلاثة بكل مجموعة، بأسماء الإداريين والرتبة وقت القياس والنقاط ووجود صورة فقط. لا تُرسل أرقام الأداء التفصيلية للزملاء في DTO أوRLS أوالسجل.

«سجلي» يعرض أحداث العضو مع قبل/بعد. Owner وResponsible يختاران أي عضو، والعضو لا يمكنه فتح سجل زميله بطلب API مباشر. السجل والأرصدة لا يحذفان عند تغيير الرتبة أو التعطيل أو بداية شهر جديد.

## 14. تحديث مصدر Windows

فك حزمة 1.3 الجديدة إلى مجلد مستقل. من PowerShell داخل مجلد `Chico-Admins` المستخرج:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\update-from-release.ps1 -RepositoryPath 'D:\New life\Chico\Chico-GitHub'
Set-Location 'D:\New life\Chico\Chico-GitHub'
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run build:vercel
git diff --stat
git status --short
```

السكربت يتحقق من مستودع Chico ويحافظ على `.git` وملفات البيئة والتاريخ. ينقل المصدر الكامل ويحذف ملفات العرض التجريبي والصورة القديمة المتقاعدة. لا ينفذ commit أوpush. بعد نجاح الفحوص ومراجعة الملفات:

```powershell
git add -A
git commit -m "Release Chico Admins 1.3"
git push origin main
```

اجعل Root Directory في Vercel هو المجلد الذي يحتوي `package.json` و`app/` و`vercel.json`. لا ترفع مجلدًا أبًا يجعل `app/` خارج جذر البناء. إذا ظهرت ملفات `.env` في staging، أخرجها قبل commit؛ الحزمة لا تتضمنها. سكربت Windows مراجع في المصدر لكنه لم يُشغّل على جهاز المستخدم هنا.

## 15. التنبيهات

الجرس والعداد يعتمدان على الإشعارات غير المقروءة للحساب الحالي، مع تحديث خفيف كل 15 ثانية عند ظهور الصفحة. عند وصول جديد تظهر رسالة قصيرة وهالة حول الجرس. صفحة التنبيهات تدعم قراءة واحدة أوالكل وتحميل الأقدم. لا يوجد Push خارج المتصفح أورسائل Discord آلية.

إنشاء الطلب أوالقرار أوالتقرير أوالنقاط أوتغيير الرتبة والمناوبة والحساب يولد إشعارًا داخل المعاملة نفسها. توجد تنبيهات دخول وتغيير كلمة المرور وإصدار الاستعادة وإنهاء الجلسة. التنبيهات العامة للإعدادات والسياسات والاجتماعات لا تحمل إحصائيات أعضاء. تنبيهات الإدارة لا تظهر بعد خفض الرتبة، بما في ذلك صفوفها القديمة. لا تتضمن كلمات مرور أوIP أوUser-Agent أوبيانات تدقيق خام.
